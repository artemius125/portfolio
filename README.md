# Портфолио: LLM-сервисы и бэкенд на Python

Инженер-бэкендер с фокусом на прикладных LLM-системах. Делаю сервисы, где модель — часть
продукта, а не демо: с детерминированным ядром, защитой от галлюцинаций, ограничением
расходов, панелью управления для не-инженеров и внятным поведением при отказах внешних API.

Ниже — восемь кейс-стади. Первые шесть — отдельные продукты одного заказчика; два
последних разбирают разные контуры одной агентной платформы для работы с документами и
относятся к текущему месту работы. Заказчики и их домены обезличены, исходный код не
публикуется: это разбор задач, архитектуры и инженерных решений, написанный по факту
сделанного. Метрики приводятся только там, где их подтверждают код, конфигурация, замеры
или тесты; там, где чисел нет, честно сказано, что их нет.

## Стек

**Языки и рантайм:** Python 3.10+ (async/await), в контейнерах 3.12; немного JS для
встраиваемых виджетов.

**Веб:** FastAPI, Starlette, SSE-стриминг, Flask + HTMX там, где не нужен SPA;
server-rendered Jinja2-админки вместо фронтенд-сборки.

**Данные:** PostgreSQL, SQLAlchemy 2.x (async, `asyncpg` / `psycopg` 3), Alembic-миграции,
`JSONB`, частичные индексы, upsert-идемпотентность, advisory-локи, ретеншн-политики.

**LLM:** OpenAI-совместимые API (шлюз-агрегатор моделей), модели класса `gpt-4.1-mini`,
`qwen3.7-plus`, `deepseek-v4-*`, эмбеддинги `text-embedding-3-large`. Function calling,
JSON-режим, стриминг, отдельные агентные циклы с ограничением шагов, LLM-as-judge,
пакетная офлайн-разметка под бюджетом. Учёт токенов и стоимости как продуктовая функция.

**Поиск и ранжирование:** field-weighted BM25 с IDF и нормализацией длины, лёгкий стемминг
для русского, косинусный поиск по эмбеддингам на numpy, каскадные скоринговые пайплайны с
объяснимым разложением риска.

**Инфраструктура:** Docker, Kubernetes (реплики, RollingUpdate, readiness/liveness/startup-пробы,
requests/limits, nodeSelector и tolerations), Helm values, GitLab CI (шаблонный Auto DevOps
и собственные джобы с `helm upgrade --install`), Loki + Grafana для логов, Sentry.

**Документы и форматы:** python-docx, openpyxl, python-pptx, pypdf, reportlab, Pillow;
LibreOffice как конвертер последней надежды; распознавание сканов под бюджетом страниц.
Приёмка артефактов независимыми парсерами, а не инструментами самого продукта.

**Межсервисное:** gRPC с protobuf-контрактами, JSON Schema и Pydantic на границах,
guided decoding по схеме на форсированных вызовах модели, ключи идемпотентности на шаг.

**Инженерная гигиена:** pytest с фейковыми LLM-клиентами (сеть в тестах не нужна),
golden-тесты и eval-харнессы с ассертами на метрики, приёмочные корпуса из реальных
документов с проверяемым провенансом (sha256 в манифесте), fail-closed конфигурация,
санитайзинг секретов в логах, обезличивание персональных данных в датасетах. ruff и mypy
в проверках.

## Как читать эти кейсы

Каждый документ построен одинаково: задача и контекст с реальными ограничениями →
архитектурная диаграмма → стек по фактам → инженерные решения с альтернативами и платой за
выбор → что было сложно (с настоящими багами и инцидентами, а не абстракциями) →
результат → моя роль.

Самое интересное — четвёртый и пятый разделы. Там видно, как выглядят настоящие компромиссы:
почему in-memory rate-limit вместо Redis, почему policy-lock сильнее вердикта модели, почему
дедлок на блокирующем `readline()` проявился как «два неуспешных запуска подряд», почему
калибровка порога иногда доказывает предел подхода, а не находит оптимум, и почему порог
сохранности, недостижимый при корректной работе, — дефект теста, а не продукта.
